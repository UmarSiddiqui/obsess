## Positioning

**/obsess**

**One thing. Unreasonable attention to detail.**

Your coding agent's perfectionist mode. Point it at one detail. It checks the first attempt and keeps working only while there's a supported improvement to make.

## Launch post

> Sometimes I don't need my coding agent to rebuild the page.

>
> So I built `/obsess`.
>
> `/obsess over this toggle and make the transition super smooth`
>
> It stays on that detail, checks its work and keeps the best-supported version. There's a small-budget `--lite` profile too.
>
> Not an endless loop. Just a coding agent that doesn't call an unchecked first attempt “done”.

## Demo worth recording

Show an actual flawed toggle or a button that clips in its real layout. Run the skill and capture the inspected result. Include a failed attempt if one occurs; rejecting it is part of the product.

Use the same content and viewport before and after. For motion, use a real recording rather than a still screenshot. Show the final report with its verification limits. A no-change result is valid, even though it isn't the strongest launch demo.

## Before a public release

Complete a host-level smoke test for each advertised integration. Run a matched-budget model comparison before claiming effectiveness or savings. Choose a licence and verify the intended repository name. Replace any illustrative material with real evidence.

The name is `/obsess`, not a clinical claim. Position the experience around focused attention rather than presenting OCD as a productivity feature.
